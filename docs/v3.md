# AI Chat Overhaul Plan v3

Supersedes v2. Goal: reframe `ai_trip_chat` as a **quick idea engine** — the user opens it to grab a trip, a place, or a single activity they can run with in under a minute. Typing is optional. Every card is image-led, and every card is a real, reusable object the rest of the app already knows how to render.

v3 keeps every v2 deliverable and adds three new pillars:

1. **Image-led cards.** Curated trip cards, destination rows, and place rows all fetch hero images the way `HomePage` does — through `DestinationImageRepository` / Wikimedia — and cache them per trip / destination / venue. Place cards reuse Yelp photos directly.
2. **Curated starters render through the Current Trip pipeline.** Tapping a curated trip opens a read-only preview that is the same `CurrentTripScreen` stack the app already uses for live trips. Same hero, same day-by-day, same calendar modes, same share sheet. No bespoke preview surface. Committing turns the preview into a real trip; sharing reuses `trip_card` message bubbles.
3. **Single-item chat cards reuse the `CreateEvent` add-to-itinerary pipeline.** The "restaurant / activity / event" cards in chat are the same card shape as `PlaceSuggestionCard` in `ui/main/chats/voting/CreateEventPage.kt`, and tapping "Add" routes through the same Yelp + Wikipedia enrichment that `CreateEventViewModel.selectPlace()` already does. A new shared `PlanEventDraftService` sits under both surfaces so the AI chat and the voting page share one add-event path. Ticketmaster slots in as a new provider behind the same contract.

Sections below reuse v2's phase numbering for continuity. **New phases: 1D, 2E, 3C, 3D, 8.** Existing phases gain "v3 follow-up" bullets where scope grows.

### Phase 1D (new): Curated Starter → Current Trip Preview

Goal: reuse the existing `CurrentTripScreen` to show a curated starter as a full trip, without committing it to Firestore.

Why: the Current Trip pipeline already renders hero, itinerary list, day view, week view, event detail overlays, and share sheet. Custom preview surfaces would drift. Users already know this view; showing the curated trip there is a trust signal and the CTA ("Use this trip") is familiar.

Approach:
- synthesize an in-memory `Itinerary` + `List<TravelEvent>` from `AiCuratedTripStarter` (+ its refinements from 1C) via a new `AiCuratedTripToItineraryMapper`
- preview lives in a new route (`current_trip_preview`) that hosts `CurrentTripScreen` against an in-memory data source, not Firestore
- `CurrentTripViewModel` gets a preview mode: `CurrentTripViewModel.PreviewSource.InMemory(itinerary, events)` — no Firestore listener when preview is active
- the preview surface adds a bottom action bar with two CTAs: "Use this trip" (commits via existing `NewTripViewModel` save path) and "Share draft" (opens `CurrentTripShareSheet`; sent messages carry a `trip_card` bubble but with a `previewPayload` field so the receiver can open it themselves)
- images: the hero is the resolved Wikimedia URL from 1B; per-event images use static-map fallbacks already wired into `ExpandedEventCard`; restaurant/activity events seeded from the starter stay text-only for now and fill in once Yelp enrichment runs (Phase 3B)

Deliverables:
- [ ] `AiCuratedTripToItineraryMapper` (starter + refinement state → `Itinerary` + `List<TravelEvent>`)
- [ ] `CurrentTripViewModel.PreviewSource` sealed type; preview path skips Firestore listeners
- [ ] new route `current_trip_preview` registered in `MainScaffold` inner NavHost
- [ ] preview-mode action bar added to `CurrentTripChrome` (gated on preview source)
- [ ] "Use this trip" wiring: hands the in-memory itinerary to `NewTripViewModel.commitItinerary()` (new method extracted from existing save flow)
- [ ] share from preview uses existing `CurrentTripShareSheet`; sent message encodes seed id + refinement state so the recipient can replay the preview
- [ ] AI chat "Preview trip" action navigates to `current_trip_preview` instead of auto-committing

Files:

- `ui/main/current/CurrentTripViewModel.kt`
- `ui/main/current/screen/CurrentTripScreen.kt`

### Phase 3C (new): Shared `PlanEventDraft` Pipeline

Goal: one add-event path used by `CreateEventViewModel` AND `AiChatViewModel`. Today `CreateEventViewModel.selectPlace()` does Yelp → Wikipedia → draft fields. That logic becomes the shared `PlanEventDraftService`.

Why: the user explicitly asked for the chat-folder add-event mechanism to back the AI chat. Sharing the service means a bug fix in one pipeline fixes both, and Ticketmaster (Phase 3D) only needs one plug-in point.

Scope:
- new `data/ai/chat/PlanEventDraftService.kt` with:
  - `fun draftFromPlace(place: PlaceSuggestion): Flow<PlanEventDraft>` — Yelp base + Wikipedia extract + fallback copy
  - `fun draftFromCuratedSeedSlot(seed: AiCuratedTripSeed, slotIndex: Int): PlanEventDraft` — when a curated preview row surfaces a chat recommendation
- `CreateEventViewModel.selectPlace()` delegates to the service; keeps its own `StateFlow` bindings
- `AiChatViewModel` gains `startPlaceDraft(place: PlaceSuggestion)` that emits the same draft model into the chat's active "adding event" bottom sheet

Deliverables:
- [ ] `PlanEventDraft` data class (title, description, location, date, startTime, endTime, photoUrl, source metadata)
- [ ] `PlanEventDraftService` with Yelp + Wikipedia enrichment
- [ ] `CreateEventViewModel.selectPlace()` refactored to call the service
- [ ] unit test: Yelp-only input → populated draft; Yelp + Wikipedia input → extract merged into description
- [ ] regression test the voting flow still works (no behavior change for existing users)

2. **Phase 1D preview through Current Trip** — unlocks the "this card represents a real trip" promise; turns curated cards from flyers into something actionable.
3. **Phase 3C shared `PlanEventDraftService`** — internal refactor, no visible change, but unblocks 3B and 3D cleanly.
4. **Phase 3B shared place card** — pays off 3C immediately, gives AI chat Yelp-quality imagery.
5. **Phase 3D single-item cards + Ticketmaster** — closes the loop on "quick idea, one-tap add".
6. **Phase 2E quick-idea first turn** — reframes default entry once the richer cards exist to fill the space.

Phase 1A/1C and the v2 2A–2D checklist remain valid background work; they can ship independently.
