# AI Chat Overhaul Plan v2

Goal: turn `ai_trip_chat` into a card-first TravelCents trip copilot that minimizes typing, keeps context across sessions, and can later be invoked from other app surfaces.

Each phase below is self-contained: goal, scope, deliverables (as checkboxes), and primary files. Phases 1–3 are grouped by theme with lettered sub-phases. Use the checkboxes to track progress.

---

Umbrella goal: let the AI suggest editable trip skeletons for popular destinations and let the user shape them inline.

- first-pass seed set before broadening coverage

## Phase 2: Dynamic Structured Questioning

Umbrella goal: make the model author the next best planning question instead of relying on repetitive fallback cards.

### Phase 2A: Unified Response Envelope

Status: mostly done. Envelope is wired end-to-end through `AiTripIntakeOrchestrator` and `AiChatViewModel`; the dedicated file split and end-to-end test remain.

Goal: every LLM turn returns one structured envelope. Static fallback becomes a guarded recovery path only.

Envelope fields:
- acknowledgement copy
- next planning objective
- next follow-up question
- response card options
- selection-mode metadata (single / multi)
- `allow_other` flag + typed handoff hint
- optional destination recommendations
- optional curated trip starter suggestions
- optional place recommendation intents

Deliverables:
- [x] prompt factory that requests the full envelope (currently inline in `AiTripIntakeOrchestrator` — not split into a dedicated `AiChatPromptFactory.kt` yet)
- [x] parser that reads the envelope into typed chat items (inline in orchestrator)
- [x] coordinator that routes envelope fields into the chat UI stream (inline in `AiChatViewModel`)
- [x] static fallback path marked as recovery-only and logged when triggered
- [ ] end-to-end test: intake profile → envelope → rendered chat items

Files:
- `data/ai/chat/AiChatPromptFactory.kt`
- `data/ai/chat/AiChatResponseParser.kt`
- `data/ai/chat/AiChatCoordinator.kt`
- `data/ai/chat/AiTripIntakeOrchestrator.kt` (integration point)
- `ui/main/aichat/AiChatViewModel.kt`

---

### Phase 2B: Card Schema Enforcement

Status: mostly done. All validation rules enforced in code; dedicated test coverage still pending (an `AiTripIntakeSchemaTest` exists but coverage of each edge case is not verified).

Goal: every AI-authored answer-card group conforms to a tight schema so the UI feels consistent.

Rules:
- 2–6 options per group
- max 2 words per visible label
- explicit single-select vs multi-select
- no duplicate questions within a session

Depends on: Phase 2A.

Deliverables:
- [x] parser validation for option count (enforced by `toCardGroup()` with `size in 2..6`)
- [x] parser validation for label length (≤ 2 words, via `shortenOptionLabel`)
- [x] parser validation for selection-mode presence (`allowMultiple` required in schema)
- [x] repeated-question suppression (`askedFollowUpGroupIds` + prompt guard)
- [ ] tests covering each rule, including edge cases (0, 1, 7 options; 3-word labels; repeat asks)

Files:
- `data/ai/chat/AiChatResponseParser.kt`
- `data/ai/chat/AiTripIntakeSchema.kt`
- `app/src/test/java/com/example/travelcents/data/ai/chat/AiChatResponseParserTest.kt`

### Phase 2C: `Other` Handoff

Status: mostly done. Composer honors `allow_other`, combined-turn payload ships, draft state persists; dedicated round-trip test still pending.

Goal: when presets are close but not right, `Other` should push the user into the composer instead of faking a preset answer.

Scope:
- composer enters a guided "tell me more" state when `Other` is selected
- submitted turn preserves both the structured selection and the typed explanation
- priority surfaces for `Other`: party shape, food, constraints, hotel area, destination ideas

Depends on: Phase 2A, Phase 2B.

Deliverables:
- [x] `allow_other` honored by the composer UI
- [x] composer prompt copy that clearly asks the user to type what they mean (`composerHint` from `otherPromptHint`)
- [x] combined-turn payload with selections + typed text (in `sendDraft`)
- [x] draft state preserved if the user taps away before sending (`selectedDraftOptions` + `draftText` in session state)
- [ ] test: `Other` + typed text round-trips through the envelope

Files:
- `ui/main/aichat/components/AiChatComposer.kt`
- `ui/main/aichat/AiChatViewModel.kt`
- `data/ai/chat/AiChatSessionState.kt`

### Phase 2D: Variation And Planning Drive

Status: in progress. Prompt variation rules and anti-repetition exist; UI surfacing of planning goal and sampling tests are pending.

Goal: same session should not feel cloned. Every question should visibly move the user toward a concrete plan.

Scope:
- prompt-side variation so the same field gets phrased differently across sessions
- acknowledgement copy varies rather than templating
- planning-goal signal attached to each turn so the UI can show forward motion

Depends on: Phase 2A.

Deliverables:

- [x] anti-template acknowledgement copy guidance (system prompt: "sounds naturally authored for this exact trip discussion, not templated")

- [x] anti-repetition heuristic so similar vibes do not produce identical chats (`askedFollowUpGroupIds` + prompt guard)
- [ ] sampling test: two sessions with the same intake should differ in wording

## Phase 3: Destination And Place Recommendations

Umbrella goal: recommend where to go first, then what to do, eat, and stay once direction is clear.

### Phase 3A: Destination Recommendations

Goal: recommend destinations when the user has a vibe but not a locked city.

Scope:
- grounded in trip type, pace, budget, food interests, season, origin
- each suggestion includes a short match reason
- tapping a suggestion either refines further or jumps into Phase 3B place recs
- suggestions that map to Phase 1A seeds should link into curated starters

Depends on: Phase 1A, Phase 2A.

Deliverables:
- [ ] `AiChatItem.DestinationRecommendationRow`
- [ ] recommendation engine: intake profile → ranked destinations
- [ ] per-row match-reason copy (short, plain language)
- [ ] bridge: selected destination with a seed → curated starter row
- [ ] bridge: selected destination without a seed → refinement question

Files:
- `data/ai/chat/AiDestinationRecommendationEngine.kt`
- `data/ai/chat/AiRecommendationMapper.kt`
- `data/ai/chat/AiChatItem.kt`
- `ui/main/aichat/components/AiRecommendationRow.kt`

---

### Phase 3B: Place Recommendations

Goal: once destination confidence is high, recommend what to do, eat, and where to stay inside the trip.

Row types: restaurants, hotels / hotel areas, activities, neighborhoods, day-trip ideas.

Scope:
- coordinator decides when to emit place vs destination rows
- provider orchestration through Yelp and Serp, blended with curated seeds
- per-row actions: swap, save, add (see Phase 4)

Depends on: Phase 3A, Phase 4.

Deliverables:
- [ ] `AiChatItem.PlaceRecommendationRow`
- [ ] coordinator logic for destination-confidence threshold
- [ ] Yelp-backed restaurant and activity rows
- [ ] Serp-backed hotel rows
- [ ] match-reason copy per row
- [ ] action stubs (swap / save / add) wired but disabled until Phase 4

Files:
- `data/ai/chat/AiPlaceRecommendationCoordinator.kt`
- `data/trip/remote/YelpRepository.kt`
